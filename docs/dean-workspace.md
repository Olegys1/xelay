# Кабінет деканату

Маршрут `/dean` використовує особистий вхід Xelay, перевірену MFA та чинну сесію.
Адміністратор із 2FA створює окремі службові входи. Логін має формат email, але не є поштовою скринькою. Випадковий пароль показується один раз і не зберігається у чернетках, журналах чи коді. Працівник налаштовує свій другий фактор. Вхід відкликається адміністратором. Права не беруться з user_metadata; Auth Admin позначає створений ним акаунт у захищених app_metadata. Створення не підміняє особисту згоду працівника.

## Робочий процес

Створення службового входу спочатку резервує точний UUID та логін на дві хвилини через чинну адміністративну MFA-сесію. Це враховує порядок Auth Admin (спочатку INSERT, потім app_metadata). Випадкова звичайна реєстрація, інший UUID/логін, прострочений дозвіл чи відкликана сесія не отримують цього винятку.

1. `/dean`: відкрити хмарну чернетку, обрати умови, натиснути «Запропонувати інші варіанти». Розрахунок відбувається на сервері, без локальної програми. Обрати студента або викладача для перегляду; натиснути заняття, задати новий день і пару, щоб підібрати пов’язані перенесення. Результат відкривається тільки як нова чернетка. Спільна початкова версія доступна працівникам лише для читання.
2. Для публікації окремо обрати понеділок першого навчального тижня, один раз прив’язати студентів до акаунтів у дозволених адміністратором групах. Імена не використовуються для автоматичної ідентифікації.
3. Зберегти чернетку. Версії зберігаються у приватній схемі; їх немає у відкритих файлах сайту.
4. «Перевірити публікацію»: сервер перевіряє склад, права, накладки, навантаження 2–4 пари, відсутність вікон, 5 днів (або 3–4 для навантаження менше 10 пар), лабораторні до 18 осіб та конфлікти з чинним розкладом.
5. Адміністратор погоджує точний номер версії. Наступне редагування скасовує погодження. Окрема кнопка публікує погоджену версію атомарно. Повторний запит не створює дублікати.

Жодна чернетка сама не публікується. Поточне доручення не дозволяє публікацію студентам.
Перед першим реальним запуском потрібне підтвердження власника Xelay, точний календар та перевірена повнота вихідних годин. Дата початку семестру не виводиться з припущень.

## Збереження старого розкладу

`study_group_schedule` не змінюється. Нові персональні заняття — окрема проєкція, доступна тільки своєму студенту після перевірки членства і сесії. Склад інших підгруп не передається. Вони відображаються в наявному розкладі групи та на головній через спільний читач. Редагування цих занять через звичайний редактор групи вимкнено.
Опубліковані версії незмінні. Для редагування створюється копія; автоматичної заміни чинних занять у цьому випуску немає. Перевірка чинних групових записів консервативна: чергування тижнів потребує ручної звірки при повідомленні про конфлікт.

## Межі першого підключення

OR-Tools працює у Python-функції Vercel `/api/dean`. До 600 шаблонів, 5000 студентів, 30 тижнів та 250000 зв’язків участі. Два варіанти з лімітом пошуку 25 секунд кожний; незалежна перевірка кожного результату. Відсутність знайденого рішення за цей час не означає доведену неможливість. Оптимальність не гарантується. Змінюються тільки день і пара; години, склад потоків та призначення викладачів незмінні.
Один активний розрахунок на користувача, два на сервіс, до 40 на добу на користувача. Результат прив’язаний до чинної MFA-сесії та ревізії чернетки. Після перезавантаження історія доступна онлайн. Застаріла ревізія, відкликаний доступ чи завершена сесія не дозволяють застосувати результат. Python-пакети зафіксовані версіями й SHA256; їхні тести та перевірка відомих вразливостей обов’язкові в CI.
У вихідних таблицях є неповні години; перевірка розміщення пар не доводить повноту навчального плану. Рішення про повноту залишається окремою перевіркою деканату.

## Перевірки

`tests/dean-workspace.test.mjs`: справжній локальний PostgreSQL, MFA, прострочена сесія, доступ груп, відкликання, збереження, версії, накладки, заборона публікації без підтвердження, персональна видимість, повтор запиту, незмінність чинного розкладу.
`tests/dean-schedule-read.test.mjs`: завантаження історії, пагінація, зміна акаунта/застаріла відповідь, відмова авторизації.
Обидва файли додано до обов’язкової перевірки CI. Локальний UI-приклад: `node scripts/preview-dean-workspace.mjs --port 3171`, тільки вигадані дані, мережа до робочої бази вимкнена.
`tests/dean-online-database.test.mjs`: службові входи без підроблення згоди, MFA, приватні результати, незмінність оригіналу, повтор застосування, відкликання доступу. `tests/test_dean_online.py`: реальний розв’язувач, каскадні перенесення, неможливі умови, збереження годин, межі API та серверна авторизація.
