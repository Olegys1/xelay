User authorization: 2026-11-16. Student prices: Start149, Plus399, Max999 UAH per subscription month. Only Max includes a model allowance: internally up to10 USD per paid grant period, with no calendar-month double reset. The public catalogue describes a limited AI allowance without displaying its dollar amount. There is no automatic renewal or automatic paid overage. Existing Participant paid time, gifts and lifetime benefits remain; they do not become unlimited model allowance.

## Access and data boundaries

`/api/student-learning` is the sole new authenticated server function, with allowlisted status/history/generate/progress actions. It verifies the real Supabase user/session, immutable server billing identity and current grant. Student role/cost/model fields supplied by a browser are not authority. Same-origin writes, bounded JSON, input/output moderation, strict artifacts/literal citations, rechecks and atomic quota settlement remain required. A single user has a persistent cap plus bounded generation concurrency/rate. In-process throttling is supplementary; the database enforces distributed generation limits.

The private schema holds grants/periods, source choices, reservations, runs and revisioned progress. Model costs and request fingerprints are idempotent per owner/request. Unknown costs remain conservatively accounted for. A revoked session or stale context cannot store/show an accepted generation. Ordinary chat may run without a source; source-based activities require selected own notes/excerpts. The server may add the authenticated owner's bounded profile context (name, faculty, specialty and study year), selected own conversation history and practice summaries. Browser-supplied identity/context is not authority. This is not unrestricted access to the account: the endpoint cannot retrieve official teacher tests, keys, grades or protected originals by a URL. Max does not mutate teacher grades.

The UI isolates local tools, PDF databases, draft/outbox and hints by owner. New production workspaces start without synthetic questions, cards, marks or projects. Answer saves use server revisions and a local pending queue; incompatible updates from another tab are preserved for export instead of silently overwritten. New activity is gated after expiry, while own reading/export remains available. Device-labelled tools remain local; generated sessions/answers are server-backed.

The unified conversation supports ordinary questions and inline learning activities. «Авто» selects an activity from the visible request; explicit selection remains possible. Source-based formats include quizzes, cards, plans, true/false, gap filling, smart reading, written answers, exercises and a learning dialogue. Side hints are opt-in typed aggregate events, not whole-screen scraping or hidden model calls. They can be paused/dismissed/snoozed, and local reminders operate only while the studio is open. The old global helper is suppressed on `/learning` to avoid overlapping launchers.

## Teacher tests during connection loss

Before sending an answer, the browser retains a bounded local copy scoped to the owner, test, attempt and question. Reconnection/reload first obtains authorized server state, then retries only the matching current question/version while its deadline remains open. Server confirmation removes only the exact accepted draft. Conflicts or late drafts remain available for review/export; they are not silently overwritten or automatically credited after the deadline. Blocked storage, a cleared browser/device or logout can prevent local recovery; this is not a promise of unlimited offline testing.

The copy contains answers and identifiers, never question content, answer keys, access codes, authoritative time or grades. Server timers, locks, admission, session ownership and anti-tab/exit rules remain authoritative. Losing the connection does not pause a timer or exempt a recorded exit; a protected exit can submit the attempt. Confirmed logout/account-session changes clear the answer outbox. No teacher-test database migration is needed for this client recovery change.

## Billing identity and time

Historical editable profile metadata cannot prove the original registration type. Such records are not guessed or mass-migrated. The first verified new student purchase may establish an immutable declared student billing choice; a service-only audited assignment can resolve an intended account. Adding teaching capabilities does not subsequently change that identity. Known teacher accounts retain the legacy Participant purchase path until separate teacher tariffs are introduced.

New orders snapshot plan/amount. Only a verified live approval applies a real paid grant; pending/refunded/voided orders cannot grant Max. Test payments are isolated and must not become real entitlements. Higher-tier purchases preserve lower-tier remaining time in audited period segments. Same/lower-tier purchases queue without discarding paid time. One payment receives one model allowance even if refund reflow moves its preserved duration across a calendar boundary. Nonpayment gifts follow their own Kyiv anniversary windows. Migration carries settled costs and in-flight reservations forward without issuing a fresh allowance; refunds revoke only the matching grant and retain incurred costs. Legacy premium capabilities remain available for every active paid private period.

Administrator Start/Plus/Max grants require the existing second factor and an audit trail. New birthday offers are one seven-day coupon: Start50%, Plus30%, Max20%, without stacking or duplicate redemption. Existing birthday gifts remain valid.

Do not treat model-schema validity, a literal quotation or a generated answer key as a guarantee of factual correctness. The Astra reference is limited to accessible screens; subscription-only flows were not tested, and no completeness,90% parity or superiority claim is made. Dictation and narration depend on browser support and explicit user action; the learning dialogue uses browser voices with a text transcript, not a downloadable generated audio file. Photo/scanned-PDF OCR and3D simulations are not implemented. File extraction is bounded and discloses cropped excerpts.
