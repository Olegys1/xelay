# Підтвердження пошти та відновлення пароля

Код уже підготовлений. Фактичне надсилання потребує налаштування Supabase та поштового сервісу. Виконайте кроки в цьому порядку, щоб реєстрація продовжувала працювати.

## 1. Застосувати дві міграції

У Supabase відкрийте SQL Editor → New query. По черзі відкрийте файли проєкту, скопіюйте **весь вміст** кожного файла та натисніть Run:

1. `supabase/migrations/202610010003_auth_email_confirmation.sql`.
2. `supabase/migrations/202610010004_email_notifications.sql`.

Перша створює профіль на сервері під час реєстрації, навіть коли підтвердження пошти ще очікується. Без цього реєстрація з Confirm Email не зможе створити профіль. Друга додає налаштування й чергу листів, а сповіщення про відповіді створює сама база. Попередні міграції проєкту мають уже бути застосовані.

Існуючі профілі та ролі не перестворюються. Нові ролі й підписки ніколи не беруться з даних реєстраційної форми. [Профілі та тригери Supabase](https://supabase.com/docs/guides/auth/managing-user-data).

## 2. Опублікувати новий код

Збережіть зміни в Git, відправте у GitHub і дочекайтеся нового deployment у Vercel. Відкрийте `https://www.xelay.ink/reset-password`: без листа має показатися «Посилання недійсне» і кнопка запиту нового посилання. Це очікувана поведінка — звичайна відкрита сторінка не дає змінити пароль.

## 3. Підключити Resend до Supabase SMTP

1. У Resend додайте домен `xelay.ink` і внесіть DNS-записи, які покаже Resend. Дочекайтеся Verified. Записи сайту у Vercel не видаляйте.
2. Створіть API key з правом надсилати листи. Для Auth можна використати окремий ключ того самого підтвердженого домену.
3. У Supabase відкрийте Authentication → Email / SMTP Settings (назви розділів можуть відрізнятися) та увімкніть Custom SMTP.

| Поле | Значення |
| --- | --- |
| Sender email | `auth@xelay.ink` або адреса вашого підтвердженого піддомену |
| Sender name | `Xelay` |
| Host | `smtp.resend.com` |
| Port | `465` |
| Username | `resend` |
| Password | API key Resend |

Цей пароль вводиться **в SMTP Settings Supabase**, а не в `.env.local` чи код сайту. [Підключення Resend SMTP](https://resend.com/docs/send-with-supabase-smtp).

Стандартний відправник Supabase призначений для обмежених перевірок, тому для реальних користувачів потрібен Custom SMTP. [Обмеження стандартного відправника](https://supabase.com/docs/guides/auth/auth-smtp).

## 4. Налаштувати посилання

У Authentication → URL Configuration:

**Site URL:** `https://www.xelay.ink`

У **Redirect URLs** додайте кожну адресу окремо:

```text
https://www.xelay.ink/auth/callback
https://www.xelay.ink/reset-password
https://xelay.ink/auth/callback
https://xelay.ink/reset-password
http://127.0.0.1:3000/auth/callback
http://127.0.0.1:3000/reset-password
http://127.0.0.1:3001/auth/callback
http://127.0.0.1:3001/reset-password
http://localhost:3000/auth/callback
http://localhost:3000/reset-password
```

Платформа використовує адресу сайту, з якого запитано лист. Для локальної перевірки посилання відкривайте на тому самому комп’ютері. Для звичайних користувачів запитуйте лист із production-сайту. [Redirect URLs Supabase](https://supabase.com/docs/guides/auth/redirect-urls).

## 5. Українські листи

У Authentication → Email Templates / Email відкрийте:

- **Confirm signup**: Subject `Підтвердіть пошту — Xelay`; HTML із `supabase/templates/confirm-signup.html`.
- **Reset password**: Subject `Відновлення пароля — Xelay`; HTML із `supabase/templates/reset-password.html`.

Залиште `{{ .ConfirmationURL }}` у кнопках без змін. Ця змінна створює одноразове посилання Supabase з адресою повернення. Не замінюйте її на звичайне посилання `/reset-password` і не додавайте до шаблону пароль користувача.

У коді використовується стандартний browser / implicit flow Supabase. Шаблони, що ведуть прямо на `?token_hash=...` або `?code=...`, без серверного обміну тут не застосовуються.

## 6. Увімкнути підтвердження

Після міграцій, deployment, SMTP та посилань відкрийте Authentication → Sign In / Providers → Email і увімкніть **Confirm Email**. Новий користувач побачить екран «Перевірте пошту» і зможе увійти після підтвердження.

Старі акаунти, які Supabase вже вважає підтвердженими, залишаються доступними. Ця настройка не надсилає їм листи повторно та не скасовує їхні сесії.

## 7. Перевірити на власних тестових адресах

1. Зареєструвати новий акаунт, перевірити лист і профіль після підтвердження.
2. Спробувати увійти до підтвердження: платформа має запропонувати перевірити пошту / повторно надіслати лист.
3. Натиснути «Забули пароль?» у вході, отримати лист, змінити пароль і увійти з новим.
4. Перевірити використане / прострочене посилання та невідповідність двох паролів.
5. Відкрити `/reset-password` без листа у звичайній сесії: форма нового пароля має бути закрита.

Повторна відправка має паузу 60 секунд, а Supabase додатково застосовує власні ліміти. Якщо листи не надходять, перевірте Auth Logs Supabase, Resend та Spam. Відключіть link tracking для Auth-листів; поштові сканери можуть використати одноразове посилання раніше за користувача.

При `Database error saving new user` перевірте Auth Logs та наявні тригери:

```sql
select tgname, pg_get_triggerdef(oid)
from pg_trigger
where tgrelid = 'auth.users'::regclass and not tgisinternal;
```

Не видаляйте сторонні тригери навмання: старий тригер, який ще раз вставляє той самий профіль, потрібно узгодити з новим.

## Дублювання звичайних сповіщень

SMTP відповідає за підтвердження й відновлення. Щоб надсилати також події платформи, виконайте `XELAY_EMAIL_NOTIFICATIONS_SETUP.md`: потрібні серверні змінні Vercel, Database Webhook і задача повторних спроб.

«Вимкнути сповіщення» в колокольчику вимикає індикатор та звичайні листи. «Дублювати на пошту» вимикає тільки листи. Лист підтвердження / відновлення пароля працює незалежно від цих перемикачів.

Звичайний `npm run dev` відкриває інтерфейс і працює з Supabase Auth. Серверні Vercel API доставки листів запускаються після deployment; їх не обслуговує Vite.
