# Xelay

Xelay — університетська платформа для обміну знаннями, досвідом і можливостями між студентами та іншими учасниками спільноти.

## Current application

Поточна версія підтримує реєстрацію та вхід, обговорення за темами, відповіді, пошук учасників за ніком, розширені профілі, запити на спілкування та особисті чати після прийняття запиту. Офіційні новини факультету та загальні новини університету розміщені у вкладках розділу «Новини», з окремими редакторськими доступами.

Перед використанням нових функцій послідовно застосуйте міграції `supabase/migrations/202609260001_profile_connections_messages.sql` і `supabase/migrations/202609270001_usernames.sql` у SQL Editor відповідного проєкту Supabase. Пошук працює за ніком; особистий чат створюється лише після прийняття запиту його отримувачем.

## Stack

- React і TypeScript
- Vite
- TanStack Router
- Supabase Auth, Postgres і Storage
- Tailwind CSS

## Local setup

1. Встановіть залежності командою `npm ci`.
2. Додайте `VITE_SUPABASE_URL` і `VITE_SUPABASE_ANON_KEY` до `.env.local`.
3. Запустіть локальний сервер командою `npm run dev`.

Зберіть production-версію командою `npm run build` і перевірте типи командою `npm run lint:types`.

## Плавність та повідомлення про дії

Спільний `ToastProvider` показує короткі повідомлення про успіх, помилки
та поля, які потрібно заповнити. Повторне повідомлення з тим самим `id`
оновлює наявне; таймер зупиняється під час наведення, фокусу або приховування
вкладки. Повідомлення можна закрити вручну, вони оголошуються читачем екрана.
Нативна перевірка обов’язкових полів підсвічує помилки й переводить фокус
до першого поля. Профіль додатково перевіряє університет, факультет і програму.

Нові дії підключають `useToast` з `src/context/ToastContext.tsx` і викликають
`notify({ id, tone, title, description })` після підтвердженого результату.
Фонові оновлення не повинні створювати повторні повідомлення. Якщо запис
збережено, а завантаження файлів або оновлення списку не вдалося, показується
попередження з поясненням часткового результату.

Вікна, меню, помилки й нові повідомлення мають короткі анімації. Історія чату
не анімується повторно; розміри повідомлень і положення прокрутки зберігаються.
Усі нові ефекти враховують `prefers-reduced-motion`. Додаткові пакети,
ключі чи міграції бази даних для цього доопрацювання не потрібні:
достатньо опублікувати оновлений код у Vercel.
