# Xelay: что вставить для подключения оплаты

Обновлено 30.09.2026. Код подготовлен локально; реальные покупки выключены.
Эта инструкция не означает, что магазин уже активирован или что платежные
сценарии проверены на настоящей базе.

## 1. Что уже предусмотрено

- «Учасник»: 100 грн за один календарный месяц, продление вручную.
- Группа: 750 грн один раз за конкретную группу, на время работы Xelay.
- Первая созданная группа на всей платформе получает доступ бесплатно. Это
  не первая группа каждого старосты; удаление группы не повторяет акцию.
- Нет Mega, Ultra, автоматического продления или автоматических списаний.
- Доступ открывает сервер после проверки подтверждения WayForPay. Возврат
  в браузере на страницу Xelay сам по себе не подтверждает оплату.
- Повторное подтверждение не добавляет ещё один оплаченный месяц.
- Подтверждённый полный возврат отзывает доступ именно по этому заказу.
- Тестовые заказы записываются отдельно и не выдают реальные платные права.

## 2. Что вставить в Supabase

1. Сначала проверьте новую миграцию на отдельной тестовой базе, где уже
   применены предыдущие миграции проекта.
2. Откройте файл `supabase/migrations/202609300001_participant_billing.sql`
   в папке проекта. Скопируйте **весь файл**, включая `begin;` и `commit;`.
3. В Supabase откройте **SQL Editor → New query**, вставьте содержимое и
   выполните запрос на тестовом проекте.
4. Если запрос выдал ошибку, сохраните текст ошибки и не выполняйте
   отдельные куски SQL: миграция рассчитана на одну транзакцию.
5. Применение на рабочем проекте — после проверки миграции, прав разных
   пользователей и платёжных сценариев на тестовом проекте.

Папка проекта на вашем компьютере:

```text
C:\Users\oleza\.codex\.chatgpt-projects\g-p-69774e1464188191817a0344a1fda86f\xelay
```

Чтобы скопировать файл: откройте его в VS Code, нажмите **Ctrl+A → Ctrl+C**,
перейдите в новый запрос SQL Editor и нажмите **Ctrl+V → Run**. Для миграции
выберите роль `postgres` в SQL Editor. Файлы `src/`, `api/` и `server/` уже
изменены в этой папке — повторно вставлять в них код не нужно.

Предыдущие файлы, в порядке применения:

1. `202609260001_profile_connections_messages.sql`
2. `202609270001_usernames.sql`
3. `202609280001_universities_news_admin.sql`
4. `202609280002_message_interactions.sql`
5. `202609280003_private_message_media.sql`
6. `202609290001_study_groups_schedule.sql`

Если эти изменения уже есть в базе, снова вставлять старые миграции не
нужно. Новая миграция включает защиту повторного применения своих политик.
Она не удаляет профили, чаты, расписание или домашки.

## 3. Что вставить в Vercel сейчас, пока ФОП и магазин не готовы

Откройте **Vercel → проект Xelay → Settings → Environment Variables**.
Каждая строка ниже — отдельная переменная: слева её имя, справа значение.
Выберите окружение **Production**. После изменений понадобится новый deploy.

| Имя | Значение сейчас | Откуда взять |
|---|---|---|
| `BILLING_MODE` | `disabled` | Вставьте именно это слово |
| `BILLING_CHECKOUT_ENABLED` | `false` | Покупки остаются выключены |
| `BILLING_TEST_ISOLATED` | `false` | Рабочая база не является тестовой |
| `WAYFORPAY_LIVE_APPROVED` | `false` | До активации магазина |
| `XELAY_PUBLIC_URL` | `https://www.xelay.ink` | Основной адрес сайта |
| `WAYFORPAY_MERCHANT_DOMAIN` | `www.xelay.ink` | Тот же домен без `https://` и `/` |
| `SUPABASE_URL` | `https://ВАШ_PROJECT.supabase.co` | Project URL рабочего проекта Supabase |
| `SUPABASE_ANON_KEY` | Ваш публичный ключ Supabase | Тот же публичный ключ, который использует сайт |
| `SUPABASE_SERVICE_ROLE_KEY` | Ваш серверный ключ `service_role` | Supabase → Settings → API Keys |

Значения с «ВАШ» — примеры, их нужно заменить. Серверный ключ нельзя
добавлять с префиксом `VITE_`, публиковать в GitHub или вставлять в сообщения.
В Vercel храните его как секретную переменную. Приложение также поддерживает
старое имя `SUPABASE_SERVICE_ROLE`, но достаточно **одного** серверного ключа.

Уже существующие `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` сохраняются.
Они нужны интерфейсу и должны указывать на тот же проект Supabase, что
серверные `SUPABASE_URL` и `SUPABASE_ANON_KEY`.

`WAYFORPAY_MERCHANT_ACCOUNT` и `WAYFORPAY_SECRET_KEY` сейчас можно не
добавлять. Шаблон без секретов находится в `.env.server.example`.
Копировать код по отдельным блокам в компоненты приложения не требуется.

## 4. Что нужно от вас для настоящего WayForPay

Для полноценной работы с выплатами WayForPay описывает активацию продавца:
данные магазина, реквизиты выплат, документы, договор и подтверждение
личности. В опубликованном списке документов указаны варианты ФОП и
юридического лица. Возможность выплат обычному физлицу для вашего сервиса
нужно отдельно подтвердить у WayForPay; подготовленный код такого разрешения
не заменяет. Пока продавец не оформлен и не одобрен, реальные покупки Xelay
остаются выключены. [Активация магазина](https://help.wayforpay.com/view/1737806),
[документы](https://help.wayforpay.com/view/13730003).

Для варианта с ФОП подготовьте выписку из ЕГР, документ, удостоверяющий
личность, ИНН и реквизиты выплат; окончательный перечень покажет кабинет
WayForPay. Налоговый режим и необходимость фискализации именно вашей услуги
нужно согласовать с бухгалтером. [Официальный перечень документов](https://help.wayforpay.com/view/13730003).

Перед активацией разместите реальные реквизиты продавца, контакты,
публичную оферту, условия доступа и возвратов. Для цифрового сервиса опишите
момент активации, срок месяца и смысл бессрочного доступа группы. Эти тексты
нужно заполнить данными продавца; сейчас проект не подставляет вымышленные
реквизиты. [Требования WayForPay к сайту](https://help.wayforpay.com/uk/view/13729832).

## 5. Как проверить интеграцию без реальных денег

1. Создайте отдельный проект Supabase для тестирования и примените его
   миграции. Используйте отдельные тестовые аккаунты.
2. Подготовьте Vercel Preview с HTTPS-адресом. Все публичные и серверные
   ключи **этого Preview** должны относиться к тестовому Supabase.
3. В окружении **Preview** задайте:

   ```text
   BILLING_MODE=test
   BILLING_CHECKOUT_ENABLED=true
   BILLING_TEST_ISOLATED=true
   WAYFORPAY_LIVE_APPROVED=false
   XELAY_PUBLIC_URL=https://ВАШ_ТЕСТОВЫЙ_АДРЕС.vercel.app
   WAYFORPAY_MERCHANT_DOMAIN=ВАШ_ТЕСТОВЫЙ_АДРЕС.vercel.app
   WAYFORPAY_MERCHANT_ACCOUNT=test_merch_n1
   WAYFORPAY_SECRET_KEY=ТЕСТОВЫЙ_КЛЮЧ_ИЗ_ДОКУМЕНТАЦИИ
   ```

4. Тестовый ключ и тестовые реквизиты берите с официальной страницы;
   не используйте реальную банковскую карту для тестов.
   [Тестовые реквизиты WayForPay](https://wiki.wayforpay.com/view/852472).
5. Сделайте новый Preview deploy. Адрес в двух переменных выше должен
   совпадать с фактическим адресом этого deploy. Удобнее закрепить стабильный
   адрес Preview и не менять его при каждой сборке.
6. Серверный callback должен быть доступен WayForPay без страницы входа
   Vercel и без перенаправления на другой домен. Проверьте защиту Preview:
   она не должна блокировать `/api/billing/webhook`.
7. Проверьте успешный/отклонённый платёж, повтор одного callback, возврат,
   покупку группы не её старостой, неверную сумму и неверную подпись.
   Тестовый `approved` не должен активировать настоящую подписку.
8. Для проверки интерфейса премиума администратор может отдельно выдать
   доступ тестовому аккаунту. Это подарок администратора, не оплаченная
   выручка.

Обычный `npm run dev` показывает интерфейс Vite, но не выполняет серверные
функции `/api/billing/*`. Поэтому выключенная оплата в локальном Vite сама
по себе не означает ошибку интеграции.

## 6. Что вставить после активации настоящего магазина

Получите в настройках интеграции одобренного магазина WayForPay
`merchantAccount` и `SecretKey`. В Vercel **Production** добавьте:

| Имя | Значение |
|---|---|
| `WAYFORPAY_MERCHANT_ACCOUNT` | Настоящий `merchantAccount` магазина |
| `WAYFORPAY_SECRET_KEY` | Настоящий `SecretKey` магазина, только сервер |
| `WAYFORPAY_LIVE_APPROVED` | `true`, после подтверждения WayForPay |
| `BILLING_MODE` | `live` |
| `BILLING_CHECKOUT_ENABLED` | `true`, после успешной проверки |
| `BILLING_TEST_ISOLATED` | `false` |

Остальные значения из шага 3 сохраняются. Основной домен магазина должен
совпасть с `WAYFORPAY_MERCHANT_DOMAIN` и доменом `XELAY_PUBLIC_URL`.
Нельзя смешивать настоящего продавца с режимом `test`.

Для `https://www.xelay.ink` адрес серверного уведомления:

```text
https://www.xelay.ink/api/billing/webhook
```

Он передаётся в Purchase как `serviceUrl`; если кабинет предлагает поле
Service URL, укажите тот же адрес. Адрес возвращения покупателя передаётся
сервером для каждого заказа:
`https://www.xelay.ink/api/billing/return?orderReference=НОМЕР_ЗАКАЗА`.
Он принимает GET и POST от WayForPay, затем перенаправляет на страницу
подписки или оплаченной группы. Вставлять этот адрес вручную для каждого
заказа и переключать способ возврата в кабинете не требуется.
Оплата открывается на защищённой странице WayForPay,
с параметром `regularMode=none`; карточные данные не проходят через Xelay.
[Purchase и серверные уведомления](https://wiki.wayforpay.com/view/852102).

После изменения переменных сделайте новый Production deploy и проведите
контрольную покупку и полный возврат согласованным способом. Убедитесь,
что в обоих случаях обновились заказ и доступ. Только после этого
объявляйте приём оплат пользователям.

### Отдельно включить обязательную оплату групп

По умолчанию новая миграция сохраняет `enforce_group_payment=false`.
Во время подготовки магазина старосты продолжают редактировать группы.
Это отдельная настройка от разрешения новых покупок в Vercel.

После успешной проверки настоящего магазина скопируйте целиком
`supabase/setup/enable_group_payments.sql` в новый запрос SQL Editor и
выполните его с ролью `postgres`. Тогда новые пары, домашки и приглашения
потребуют активации группы. Первая созданная группа остаётся бесплатной.
Уже сохранённые материалы доступны участникам; удаление старых данных
остаётся возможным. Сейчас этот файл **не выполнять**.

Действие записывается в журнал. Сам скрипт не активирует WayForPay и не
выдаёт подписку «Учасник». Если потребуется отменить обязательную оплату
групп, настройку можно вернуть в `false` через администратора базы.

## 7. Если деньги списаны, а доступ пока не появился

- Нажмите обновление статуса на странице подписки. Xelay проверяет
  подтверждение сервера; для своего заказа доступна повторная проверка
  WayForPay, не чаще раза в минуту.
- `/api/billing/reconcile` принимает авторизованный POST с `orderReference`.
  Проверка владельца, номера заказа и подписанного ответа выполняется на
  сервере; чужой заказ через неё активировать нельзя.
- Проверьте заказ в кабинете WayForPay и доставку callback в Vercel.
  Номер заказа находится в истории оплат Xelay.
- При временном сбое WayForPay повторяет уведомления; сервер отвечает
  подтверждением только после записи результата в базу.
  [Уведомления](https://wiki.wayforpay.com/view/852102),
  [проверка статуса](https://wiki.wayforpay.com/view/852117).
- Возвраты пока запускаются из кабинета продавца WayForPay. Автоматическая
  кнопка возврата в Xelay не реализована; частичные возвраты не моделируются
  как пропорциональное сокращение месяца. Для этого MVP используйте полные
  возвраты с проверкой обновления доступа.
- Предупреждение о повторной оплате уже активной группы требует проверки
  продавцом и возврата лишней оплаты. Возврат не запускается автоматически.
- Комиссия из callback не входит в подписанные поля. Пока её отдельно
  не сверили с отчётом продавца, Xelay показывает неполные данные комиссии,
  а не подтверждённый чистый доход.

## 8. Как временно остановить новые покупки

Поставьте в Vercel `BILLING_CHECKOUT_ENABLED=false` и сделайте redeploy.
Сохраните `BILLING_MODE=live`, продавца, SecretKey и серверный ключ Supabase.
Так новые заказы выключатся, а подписанные подтверждения старых платежей
и возвратов продолжат обрабатываться. Не удаляйте платёжные ключи и не
меняйте режим действующего продавца, пока есть незавершённые платежи.

## 9. Что ещё должно быть проверено перед запуском

- Выполнение новой миграции и её повторное применение на PostgreSQL.
- Права обычного пользователя, администратора и серверного ключа.
- Лимит шестого поиска, истечение месяца, премиум-реакции и закрепления.
- Реальные callback/Check Status, повтор, возврат и покупка группы.
- Основной домен, мобильный интерфейс, вход/выход и прежние функции.
- Данные продавца, оферта, политика возвратов и активация магазина.

Код не обновляет рабочую базу и сайт автоматически. Файлы уже редактируются
в проекте; вручную вставляются только миграция целиком и значения Vercel.

## 10. Проверить премиум сейчас, без покупки

После применения миграции войдите аккаунтом с ролью `ADMIN`, откройте
**Адмін-панель → Оплати та підписки → Надати місяць доступу від адміністратора**.
Вставьте ссылку на нужный профиль (`https://www.xelay.ink/user/ID`) и причину,
например «Перевірка запуску підписки». Нажмите **Надати 1 місяць**.
У аккаунта появятся премиум-возможности без оплаты; в выручке подарок
не учитывается. Используйте тестовый аккаунт для проверки.

Если администратор ещё не назначен, роль назначается владельцем базы через
существующую настройку ролей проекта. Не нужно вставлять серверный ключ
в браузер, менять признаки подписки в localStorage или открывать доступ
к платёжным таблицам обычным пользователям.

## 11. Чтобы изменения появились на xelay.ink

1. Откройте указанную папку проекта в VS Code.
2. В **Source Control** проверьте изменения. Файлы `.env.local` и файлы с
   реальными ключами не включайте; `.env.server.example` содержит только шаблон.
3. Сохраните изменения коммитом и отправьте в GitHub в ту ветку, которую
   Vercel использует как **Production Branch**. Проверить её можно в
   настройках проекта Vercel.
4. Настройте переменные из шага 3 этой инструкции. Если код уже отправлен,
   после настройки переменных запустите **Redeploy** нужного deployment.
5. Дождитесь статуса **Ready**, откройте `https://www.xelay.ink/subscription`.

Сначала применяются проверенные изменения базы, затем публикуется код.
Локальный предпросмотр показывает только интерфейс; для проверки оплаты
нужен Vercel deployment с серверными функциями.
