# Редагування та видалення новин

## Налаштування Supabase

Застосуйте SQL-файли у такому порядку:

1. `supabase/migrations/202609300002_news_media_links.sql` — якщо ще не запускали його для завантаження фото.
2. `supabase/migrations/202609300003_news_management.sql` — нова міграція редагування та видалення.

Для кожного потрібного файла: скопіюйте весь вміст → Supabase → **SQL Editor** → новий запит → вставте → **Run**. Перед запуском наступного запиту переконайтеся, що попередній завершився без помилки. Старі базові міграції повторювати не потрібно.

Після успішного налаштування опублікуйте код через GitHub/Vercel та оновіть сторінку.

## Як користуватися

Відкрийте новину через «Детальніше». Над публікацією доступні кнопки **«Редагувати»** та **«Видалити»** для адміністратора платформи або підтвердженого редактора її факультету.

Редагування дозволяє змінювати заголовок, короткий опис, повний текст, дату й час публікації, тип, фото, посилання, закріплення та реквізити події. Дата публікації впливає на сортування; відкладеної публікації немає. Дата події та дата публікації — окремі поля.

Фото можна зберегти, замінити або прибрати. Видалення поточного фото відбувається лише після «Зберегти зміни». «Скасувати» закриває редактор без збереження. При помилці чернетка залишається у формі.

Видалення новини потребує підтвердження. Новина, коментарі, вподобання та пов’язані сповіщення видаляються; повідомлення в чатах залишаються без посилання на цю новину. Заявка зберігається в історії зі статусом `removed`, що усуває попередню помилку зв’язку `news_submissions`.

Автор, університет, факультет та ідентифікатор новини при редагуванні не змінюються. Права перевіряються на сервері для кожного збереження й видалення.

## Перевірка на вашій базі

Після запуску SQL перевірте на тестовій новині з адміністратора/редактора: зміну тексту та дати; збереження без заміни фото; заміну й видалення фото; видалення новини, яка була опублікована із заявки. Зі звичайного користувача та редактора іншого факультету керування має бути недоступне.

Фото, на які ще посилається збережена заявка, залишаються у приватному сховищі для історії. Автоматичне прибирання таких файлів не виконується.

Міграції підготовлено локально. Їх виконання та перевірку доступу у вашому Supabase потрібно підтвердити після запуску SQL.
