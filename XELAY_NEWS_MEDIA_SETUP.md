# Фото та посилання в новинах

## Що потрібно зробити в Supabase

Перед публікацією оновлення застосуйте **один новий файл**:

`supabase/migrations/202609300002_news_media_links.sql`

1. Відкрийте файл у редакторі та скопіюйте весь його вміст.
2. Відкрийте свій проєкт Supabase → **SQL Editor** → новий запит.
3. Вставте SQL та натисніть **Run**. Переконайтеся, що немає помилки.
4. Після цього опублікуйте код через GitHub/Vercel та оновіть Xelay.

Файл передбачає, що попередня міграція університетів, новин і адміністрації вже застосована. Стару міграцію новин повторно запускати не потрібно. Новий файл можна запускати повторно: поля, обмеження, сховище та правила створюються без дублювання.

## Як користуватися

- У формі публікації або пропозиції новини натисніть **«Додати фото»** та виберіть файл з телефону або комп’ютера.
- Фото необов’язкове. Підтримуються JPEG, PNG, WebP, GIF та AVIF до 10 МБ. HEIC/HEIF потрібно зберегти як JPEG або PNG.
- Перед відправленням можна переглянути, змінити або видалити обране фото. Файл завантажується після натискання кнопки публікації/відправлення.
- Поле **«Посилання на відео або матеріали»** незалежне від фото. У повній публікації воно відкривається окремою кнопкою.
- Без фото у картці немає сірого порожнього блоку. Старі публікації із зовнішніми зображеннями залишаються сумісними.

## Доступ і перевірка після налаштування

Сховище `xelay-news-media` приватне. Фото доступне автору завантаження та користувачам, які мають право читати відповідну новину; фото пропозиції також доступне модератору. Публікація після модерації зберігає фото та зовнішнє посилання.

Перевірте на двох облікових записах: публікацію з фото; новину без фото; новину лише з посиланням; схвалення пропозиції з фото і посиланням. Користувач іншого факультету без доступу до новини не повинен отримати посилання для перегляду її фото. Помилка збереження не очищує чернетку.

Міграція підготовлена в коді. Її виконання та перевірку правил доступу на вашій базі потрібно підтвердити після запуску SQL.
