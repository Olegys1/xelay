# Xelay: Android-приложение и виджеты

Нативное приложение-компаньон для Android 8.0+ (API 26). Оно входит в существующий аккаунт Xelay и добавляет два виджета на домашний экран:

- **«Найближчі пари»** — текущая и следующие пары выбранной учебной группы, с датами. Текущая пара выделяется при перерисовке виджета.
- **«Найближче ДЗ»** — ближайшие домашние задания выбранной учебной группы.

Это отдельный APK. Установка сайта как PWA сама по себе не добавляет нативные Android-виджеты. Полный сайт открывается для остальных функций.

## Обновление виджетов в 0.1.2

У каждого экземпляра отдельно выбирается тема: как на телефоне, светлая, тёмная или Гелловин. Нажмите заголовок виджета, выберите тему и «Зберегти тему». В приложении есть наглядный пример обоих виджетов с вымышленными данными и переключателем темы.

Вместо одного завтрашнего дня расписание использует ограниченное серверное окно: сегодня и следующие 14 дней, до 24 ближайших занятий. Закончившиеся пары скрываются, а текущая отмечается по времени Киева. Для этого режима сервер должен возвращать дополнительные поля `upcoming_*`; старый ответ не выдаётся за полноценный список ближайших пар.

Ручное обновление и периодическая загрузка разделены. Ошибка одного задания или перерисовки больше не должна навсегда блокировать последующие попытки внутренним флагом. Подпись «Оновлення запитано» означает ожидание запуска; «Оновлюємо…» появляется при фактической работе. Ошибка планирования отображается отдельно.

## Исправление входа в 0.1.1

Первый отказ входа в 0.1.0 мог ошибочно отображаться как «Сесія завершилась»,
скрывая неправильные данные, неподтверждённую почту или другой ответ сервера.
В 0.1.1 эти случаи разделены: форма и почта остаются, выводится понятная причина
и статический код поддержки без пароля, токенов или исходного ответа сервера.

Обычная ошибка доступа к данным больше не удаляет действующую сессию. Выход
выполняется при явном подтверждении отзыва refresh-токена. Защищённая запись
сессии проверяется чтением после сохранения; ошибки Android Keystore получают
отдельный код `AUTH_STORAGE`. При явном новом входе старые локальные данные и
их ключ заменяются, что позволяет восстановиться после переноса повреждённого
хранилища. Открытого хранения токенов нет.

Версия имеет `versionCode=2` и тот же идентификатор приложения. Её можно
установить обновлением поверх предыдущей при совпадении подписи. Проверка
входа на конкретном Samsung пока не выполнена; один прежний текст ошибки не
позволяет установить исходную причину отказа сервера.

## Что нужно для сборки

| Компонент | Версия проекта |
| --- | --- |
| Android Gradle Plugin | 8.11.1 |
| Gradle Wrapper | 8.13 |
| Kotlin Android plugin | 2.2.21 |
| JDK для Gradle | 17 или совместимый 21 |
| Java/Kotlin bytecode target | 17 |
| Android SDK Platform | Android 16, API 36 |
| `compileSdk` / `targetSdk` | 36 / 36 |
| Минимальный Android устройства | 8.0, API 26 |

AGP 8.11 поддерживает API 36, требует Gradle 8.13 и JDK не ниже 17. Его стандартная версия Build Tools — 35.0.0. [Документация Android](https://developer.android.com/build/releases/agp-8-11-0-release-notes).

Kotlin 2.2.21 входит в опубликованный диапазон совместимости с Gradle 8.13 и AGP 8.11.1. Не обновляйте один плагин отдельно, не сверив всю связку. [Таблица Kotlin](https://kotlinlang.org/docs/gradle-configure-project.html).

JDK 21 поддерживается для запуска Gradle начиная с 8.5; это не меняет настроенный bytecode target 17. [Таблица Gradle](https://docs.gradle.org/current/userguide/compatibility.html).

В Android Studio откройте именно каталог `android`, выберите JDK 17/21 в настройках **Gradle JDK**, установите через SDK Manager платформу API 36, Build Tools 35.0.0 и Platform Tools. NDK для этого приложения не требуется. Для первой сборки нужен интернет: Wrapper и плагины загружаются отдельно.

Нужен **полный JDK с `javac` и `jlink`**, а не только среда запуска Java. Некоторые встроенные среды JetBrains содержат `java` и `javac`, но не `jlink`; на этапе упаковки Android это вызовет ошибку. Для Windows `scripts/download-jdk-windows.ps1` скачивает полный Eclipse Temurin 17 из официального API Adoptium и проверяет SHA-256, не меняя установленную системную Java.

## Публичная конфигурация Supabase

Скопируйте `local.properties.example` в `local.properties` рядом с этим README и заполните:

```properties
sdk.dir=C:/Android/Sdk
xelay.supabaseUrl=https://YOUR_PROJECT.supabase.co
xelay.supabaseAnonKey=YOUR_PUBLIC_ANON_OR_PUBLISHABLE_KEY
```

Используйте реальный путь к установленному SDK. В Windows удобно записывать его через `/`, как в примере.

Вместо двух параметров Supabase можно передать переменные окружения `XELAY_SUPABASE_URL` и `XELAY_SUPABASE_ANON_KEY`. Значения из `local.properties` имеют приоритет. Конфигурация сборки принимает HTTPS URL проекта Supabase и только публичный `anon` JWT либо `sb_publishable_…`.

URL и публичный ключ входят в APK и доступны его владельцу. Они определяют проект, а доступ к данным проверяется по пользовательской сессии и существующим серверным правам. **Не используйте `service_role`, `sb_secret_…`, пароль администратора или пользовательский токен в конфигурации сборки.** Проверка Gradle отклоняет привилегированные форматы ключей.

Для рабочего проекта Xelay запросы входа и данных проходят через существующий адрес `https://www.xelay.ink/api/supabase`, который передаёт их в тот же Supabase. Это помогает, когда прямое соединение с доменом Supabase недоступно. Проверка публичного URL проекта и пользовательских прав сохраняется; конфигурация другого проекта использует его прямой адрес.

`local.properties`, локальные APK, кэши и ключи подписи исключены из Git. Пример конфигурации и Gradle Wrapper остаются в репозитории. Сборка приложения не выдаёт права на группы, не применяет SQL-миграции и ничего не публикует.

## Сборка и установка

Из каталога `android` в PowerShell:

```powershell
.\gradlew.bat :app:assembleDebug
```

На macOS/Linux:

```sh
./gradlew :app:assembleDebug
```

Результат: `app/build/outputs/apk/debug/app-debug.apk`. Это debug-сборка для установки и просмотра на устройстве; получение APK не означает, что он уже проверен на реальном телефоне.

Для Windows с длинным путём проекта доступны переносимые инструменты:

```powershell
# Только после ознакомления и согласия с лицензией Android SDK:
.\scripts\bootstrap-windows.ps1 -JavaHomePath 'C:/path/to/jdk' -AcceptAndroidSdkLicense
.\scripts\build-windows.ps1 -JavaHomePath 'C:/path/to/jdk'
```

Первый сценарий скачивает официальные Android CLI и Gradle с проверкой SHA-256, устанавливает SDK в `.toolchain/` и создаёт Wrapper. Второй использует короткий кэш `%TEMP%/xelay-android-build`, чтобы не упереться в ограничения путей Windows. Глобальные переменные окружения не изменяются. `local.properties` по-прежнему нужно заполнить публичными параметрами проекта.

Перенесите APK на телефон и откройте его. Android может запросить разрешение на установку из выбранного файлового менеджера. Либо подключите разрешённое для отладки устройство и установите через Android Platform Tools:

```powershell
adb install -r .\app\build\outputs\apk\debug\app-debug.apk
```

Публикация в Google Play и подготовка подписанной release-сборки выполняются отдельно. Ключ подписи и его пароль не добавляются в репозиторий.

## Вход и добавление виджета

1. Откройте приложение-компаньон и войдите по электронной почте и паролю существующего аккаунта Xelay. Вход на сайте/PWA не переносит сессию в APK автоматически.
2. Регистрация и восстановление пароля открываются на сайте. Приложение не создаёт аккаунт самостоятельно.
   До входа можно нажать **«Подивитися приклад віджетів»**: это реальные Android-разметки с явно помеченными вымышленными данными.
3. На домашнем экране Android откройте список виджетов, найдите Xelay и добавьте нужный тип.
4. В настройке виджета выберите учебную группу из тех, к которым у аккаунта уже есть доступ. Настройка выполняется для каждого экземпляра отдельно.
5. Подтвердите выбор. Для изменения размещённого виджета используйте его настройки; возможности системного меню зависят от лаунчера и версии Android.

Если группы нет в списке, проверьте вступление в неё в Xelay. Виджет не позволяет читать расписание или ДЗ чужой закрытой группы и не заменяет приглашение старосты.

Учтите, что содержимое размещённого виджета видно на домашнем экране телефона.

## Обновление и ограничения Android

Используется `RemoteViews`. Периодический сигнал Android задан через `updatePeriodMillis` с интервалом час. Дополнительно зарегистрирована независимая часовая задача `JobScheduler`, сохраняемая после перезагрузки. Они запрашивают обновление, но не обещают точный запуск каждый час: энергосбережение и фоновые ограничения могут его задержать. [Обновление Android-виджетов](https://developer.android.com/develop/ui/views/appwidgets/advanced).

По нажатию «Оновити» и после настройки приложение ставит отдельную срочную задачу загрузки. На Android 12+ запрашивается expedited-режим; при отсутствии квоты используется обычное задание. Даже срочное задание зависит от сети и ресурсов системы. Короткий deadline — предпочтение планировщику, а не гарантия обновления за три секунды. Постоянного фонового сервиса нет. [JobInfo.Builder](https://developer.android.com/reference/android/app/job/JobInfo.Builder).

Начало и конец пары, полночь Киева и истечение кэша планируют локальную перерисовку через неточный `AlarmManager`. Она не требует повторного сетевого запроса, если пригодный снимок уже сохранён. Системные события загрузки, изменения времени и обновления приложения восстанавливают планирование; возврат в нативное приложение также запрашивает обновление.

Неточный будильник может заметно опаздывать, особенно в Doze. Поэтому подсветка текущей пары не гарантируется ровно в секунду начала/окончания; кнопка обновления и открытие приложения пересчитывают состояние заново. Приложение не запрашивает точные будильники и отключение оптимизации батареи. Для сохранённого задания и загрузочного события используется обычное разрешение `RECEIVE_BOOT_COMPLETED`. [Ограничения будильников](https://developer.android.com/develop/background-work/services/alarms), [Doze](https://developer.android.com/training/monitoring-device-state/doze-standby).

При выходе из аккаунта, истёкшей сессии или отсутствии сети данные не удастся обновить. Откройте приложение, при необходимости войдите снова и повторите обновление. Содержимое виджета не следует считать мгновенной синхронизацией с сайтом.

Кэш расписания и заданий шифруется ключом Android Keystore и используется не дольше 6 часов при очередной перерисовке. Датированные ближайшие пары выбираются из сохранённого окна; завтрашний список старого формата не выдаётся за новый день. Выход удаляет сессию, кэш и привязки всех экземпляров; запоздавший сетевой ответ не может восстановить данные прежнего аккаунта. Содержимое исключено из резервного копирования и переноса на другое устройство.

## Подключение сервера

Приложению нужны два ограниченных RPC из `supabase/migrations/202610180007_android_widget_snapshot.sql`. Сборка APK не устанавливает их автоматически. Порядок подключения и контракт описаны в [документации сервера](../docs/android-widget-snapshot.md).

Для режима «Найближчі пари» в 0.1.2 дополнительно нужна миграция `supabase/migrations/202610190001_android_widget_upcoming.sql`. Она применена в рабочем Xelay mvp 19 октября 2026: новый формат установлен, старый формат и точные ACL сохранены. В другом проекте применение выполняется отдельно от сборки APK.

Для рабочего **Xelay mvp** обе миграции уже применены. Проверены наличие RPC, обновление формата и закрытый доступ только для `authenticated`. Для нового вида нужен APK 0.1.2; старые APK продолжают получать прежние поля. Подпись обновления совпадает с 0.1.1, приложение можно обновить поверх предыдущего. Проверка на физическом телефоне ещё не проводилась.

Обычные ДЗ не имеют личной отметки выполнения: виджет показывает предстоящие задания. Закрытые долгосрочные задачи и уже сданные/оценённые преподавательские работы исключаются. Личный органайзер пока не включён. Задания без установленного срока не выдаются за задания с дедлайном.

ДЗ из расписания открывается на нужной дате. Преподавательские и долгосрочные задания пока ведут в раздел группы: отдельной адресации конкретного задания в веб-интерфейсе сейчас нет.

Для разработчика: конфигурационная Activity сначала возвращает `RESULT_CANCELED`; только после сохранения выбора и первого обновления — `RESULT_OK` с `EXTRA_APPWIDGET_ID`. Первое обновление организует сама Activity: при её использовании Android не вызывает первоначальный `onUpdate`. [Правила настройки виджета](https://developer.android.com/develop/ui/compose/glance/configuration).

Сеть нельзя выполнять в основном потоке `AppWidgetProvider` или `JobService`. `onStartJob` должен быстро передать работу в другой поток; завершение и отмена обрабатываются через `jobFinished` и `onStopJob`. [JobService](https://developer.android.com/reference/android/app/job/JobService).

## Если сборка или вход не получаются

- **Java не найдена:** выберите установленный JDK 17/21 в Android Studio либо задайте `JAVA_HOME` для текущего терминала.
- **SDK не найден:** исправьте `sdk.dir`; убедитесь, что установлены API 36 и Build Tools.
- **Ошибка публичной конфигурации:** заполните параметры из примера; не подставляйте серверный ключ.
- **Нет групп:** войдите в нужный аккаунт и проверьте принятые приглашения на сайте.
- **Виджет не появился после настройки:** повторите добавление и завершите выбор группы; выход кнопкой «Назад» отменяет установку нового экземпляра.
- **Данные устарели:** проверьте сеть и сессию, нажмите «Оновити». Лаунчер и энергосбережение могут откладывать фоновые задачи.
